### 검증 결과와 한계

- 기준 모의 테스트 66개를 보존했고, 추가 회귀 검증을 포함한 98개가 통과했다. 기존 잠금 파일은 `httpx2`를 설치하는데 테스트가 `httpx`를 import하던 불일치를 분리본 테스트에서 맞췄다. 의존성 정의와 lockfile은 바꾸지 않았다.
- `verification/run_mock_tests.py`는 분리본 import 위치를 확인하고 실제 네트워크 연결·subprocess·프로세스 그룹 신호를 차단한다. 모델·응답·GPU·subprocess는 mock, 기록은 임시 디렉터리를 사용했다. 테스트가 출력한 자료는 본 실험 결과가 아니다.
- Cloud 손상 기록, 로컬 후처리 기록 누락, 오류 항목 OK 표시, 진단 import 자동 호출은 먼저 실패를 재현한 뒤 수정했다. 최종 결과는 `final-mock-tests.log`를 따른다. 중간 RED·통합 실패 로그도 근거로 보존하며 최종 성공으로 덮어쓰지 않는다.
- Python 구문 컴파일, 기존 테스트 메서드 66개 보존, 합성 입력 6개의 프롬프트 문자열 동일성, 기존 Bash 블록 13개의 명령 보존(표준 진입점 이름 변경 제외), 상대 링크 152개와 이동 누락을 정적으로 확인했다. 복사에서 제외한 data/results 링크 16개는 원본 대상의 존재만 확인했고 내용은 읽지 않았다. 변경 파일에 대한 `git diff --no-index --check` 결과는 `static-checks.log`에 남긴다.
- 참고 문서는 상대 링크 외 본문을 보존했고 sources 5파일·서버 셸·의존성 정의·Judge engine은 기준본과 바이트가 같다. 실제 결과·로그의 전체 내용이나 대량 해시는 검사하지 않았다. 첫 비교에서는 원본의 인계 문서 외 모든 기준 파일이 같았다. 최종 비교에서 원본 `src/llm_eval/benchmark/runner.py`에 복사 이후 줄바꿈·import 정렬 변경이 추가된 것을 확인했다. 실행 본문 AST와 import 집합은 같았으며 변경 주체는 확인하지 않았다. 이 작업은 원본 코드를 수정하지 않았고 추가 변경도 그대로 보존했다. `verification/source-drift.json`과 `source-drift.patch`에 기록했으며 종료 후 세 방향 병합에 포함한다. 그 외 기준 파일은 같았다.

4. **CODE-04:** 부모가 통합한 뒤 테스트별 10 MiB combined stdout/stderr, TLE/OLE first-trigger, 인프라 `JUDGE_ERROR`와 `judge_policy` 메타데이터를 직접 검증한다. 문서·모의 검증만으로 실제 후보 채점 완료를 표시하지 않는다.
5. **STRUCT-06:** baseline-manifest와 기준본, 그 후 변경된 원본, 분리본을 비교한다. `verification/refactor.patch`는 검토용이며 원본에 무조건 적용하지 않는다. 특히 큐 코드·README 등 추가 변경은 병합하고, 결과·로그·데이터·비밀 파일·가상환경은 복사/삭제/이동 대상에서 제외한다. 문서와 코드 경로 이동을 함께 반영한다.
6. **STRUCT-07:** 실행이 모두 끝난 뒤 원본 폴더를 형제 위치의 `local-llm-evaluation`로 변경한다. 대상 경로가 이미 있으면 덮어쓰지 않는다. `.git`·미커밋 변경·원본 결과를 그대로 보존하고 GitHub 이름과 remote URL은 바꾸지 않는다. 새 위치에서 전용 환경을 연결/재구성하고 `llm_eval.__file__`, 구형/신규 명령 도움말, 문서 링크·서버 셸의 경로를 확인한다. 분리본 `.venv`는 복사하지 않는다.
7. **EVAL-01~02:** 실제 채점·설명 평가·집계·최종 선정은 직접 진행하고 AI는 요청받은 리뷰·기록 정리를 이어간다. 커밋·푸시는 이번 범위에 없다.

다음 한 행동: **부모가 제공하는 통합 검증 근거를 확인하고 구현 검증·통합·게시 상태를 갱신한다.** 모델 재개나 실제 Judge 실행은 이 문서 상단의 현재 상태를 대신하지 않는다.
