# Local LLM과 Cloud API 비교

[발제 STEP 7](assignment.md)의 비교 축을 이 프로젝트의 실측에 맞춰 정리한다. **실측 결과와 운영 조건 분석을 절로 나누어 섞지 않는다.** 근거는 `results/benchmark`의 원본 기록과 평가 보고서 `20260917_134421_178261Z_7affc20f`다.

## 비교 범위와 분모

비교표는 이 프로젝트의 문제·실행 시점·생성 설정에 한정한 관측이다. 로컬·Cloud는 토큰 예산과 API 설정이 다르므로 통제된 모델 성능 순위가 아니다. 일부 문항의 시간 완화를 반영한 프로젝트 지표와 공식 1배 제한 결과를 구분한다.

발제 원문 기준은 Cloud 1개 × 공통 5문항 × 1회 = 5회다. 이번 수행은 [확장 기준](requirements.md#cloud-비교-확장-기준)에 따라 **Luna·Motif-3 두 제공자에 같은 10문항을 2회씩** 적용했다.

| 구분 | 모델 | 계획 | 호출 성공 |
| --- | --- | ---: | ---: |
| Local | qwen36, gemma4 | 각 20회 | 20 / 20 |
| Cloud | luna | 20회 | 20 / 20 |
| Cloud | motif3 | 20회 | 18 / 20 |

**Luna와 Motif-3의 분모를 하나의 Cloud 분모로 합치지 않는다.** 제공자·API 계열·생성 설정이 서로 다르기 때문이다. Cloud 결과는 최종 로컬 선정에 합산하지 않는다.

# 1부. 실측

## 1-1. 품질

유효 정답은 원본 후보가 AC이고 적용 제한 미만으로 전체 테스트를 통과한 경우다. 분모는 규정대로 항상 20이며 호출 실패·코드 미생성도 분모에서 빼지 않는다.

| 모델 | 유효 정답 / 20 | 공식 1배 AC | 2배 제한 전환 | 설명 평균 (n) | 최소 수정 통과 / 대상 |
| --- | ---: | ---: | ---: | ---: | ---: |
| qwen36 (Local) | 14 (70%) | 12 | +2 | 1.30 (20) | 0 / 4 |
| gemma4 (Local) | 9 (45%) | 9 | 0 | 1.70 (20) | 4 / 8 |
| luna (Cloud) | **16 (80%)** | 15 | +1 | **2.00 (20)** | 2 / 4 |
| motif3 (Cloud) | 13 (65%) | 13 | 0 | 1.56 (18) | 0 / 5 |

**이 조건에서는 Luna의 프로젝트 지표가 가장 높았다.** Cloud 두 모델을 묶어 로컬보다 우수하다고 일반화하지 않는다. 정답률은 Luna 80% > qwen36 70% > motif3 65% > gemma4 45%이고, 설명 정확성은 Luna가 20건 전부 2점으로 유일하게 만점이다.

설명 점수의 분모가 Motif-3만 18인 것은 호출 실패 2건을 설명 채점에서 제외했기 때문이다. 실패 자체는 정답률 분모 20에 남아 있다.

## 1-2. 속도

| 모델 | 평균 | 중앙값 | 최소 | 최대 | n |
| --- | ---: | ---: | ---: | ---: | ---: |
| qwen36 (Local) | 427.5s | 271.8s | 69.2s | 1,657.5s | 20 |
| gemma4 (Local) | 1,606.3s | 1,677.8s | 674.4s | 1,870.8s | 20 |
| luna (Cloud) | **254.4s** | 117.3s | 10.2s | 988.0s | 20 |
| motif3 (Cloud) | 245.7s | 242.4s | 22.7s | 500.8s | 18 |

요청 직전부터 응답 수신까지의 전체 경과 시간이며 **Cloud는 네트워크 왕복을 포함한다.** 별도로 첫 토큰 지연을 재지 않았으므로 TTFT로 표기하지 않는다.

Cloud 두 모델이 로컬보다 빠르다. 특히 Luna의 중앙값 117초는 Gemma 중앙값의 1/14 수준이다. 다만 이 비교는 **이 노트북(RTX 5060 Laptop, 8 GiB VRAM)의 로컬 실행 결과**이며 다른 장비의 절대 속도와 합치지 않는다.

생성 속도(tok/s)는 로컬만 llama.cpp 내부 값을 얻을 수 있다. qwen36 39.8, gemma4 34.1이며 **Cloud는 제공자가 서버 생성 구간을 주지 않아 `null`이고 0으로 채우지 않았다.** 따라서 tok/s로 Local과 Cloud를 나란히 세우지 않는다.

## 1-3. 토큰 사용량과 비용

| 모델 | 입력 토큰 합 | 출력 토큰 합 | reasoning 토큰 | 예상 비용 |
| --- | ---: | ---: | ---: | ---: |
| qwen36 (Local) | 17,930 | 331,402 | 미제공 | 해당 없음 |
| gemma4 (Local) | 18,060 | **1,089,071** | 미제공 | 해당 없음 |
| luna (Cloud) | 17,346 | 490,999 | 464,154 | **$0.5929** |
| motif3 (Cloud) | 13,042 | 330,636 | 미제공 | `null` |

Luna 비용 산정 근거:

- 단가(백만 토큰당): 입력 $0.20 / 캐시 읽기 $0.02 / 캐시 쓰기 $0.25 / 출력 $1.20
- 출처: `https://developers.openai.com/api/docs/models/gpt-5.6-luna`, 2026-09-16 확인
- 20회 합계 $0.5929, 건당 평균 $0.02965, 최대 $0.10242

**이 값은 추정이지 청구서가 아니다.** 결과 JSON에도 `kind: estimate_not_invoice`로 기록돼 있다. [OpenAI 사용량 페이지](https://platform.openai.com/usage)의 실제 사용 내역과는 대조하지 않았으므로 실측 청구액으로 제시하지 않는다.

**Motif-3는 확인한 공개 단가표가 없어 비용을 `null`로 남겼다.** 임의 추정치를 넣지 않았고, 비용 축에서 Luna와 나란히 비교하지 않는다.

**로컬의 장비·전력·관리 비용은 측정하지 않았다.** 따라서 로컬 비용을 0원으로 표시하지 않는다. 이미 보유한 노트북을 썼다는 사실과 총소유비용이 0이라는 것은 다르다.

## 1-4. 실측 실패 기록

| 모델 | 호출 실패 | 코드 미생성 | 비고 |
| --- | ---: | ---: | --- |
| qwen36 | 0 | 2 | 둘 다 `skijanje`, `finish_reason=length` |

# 2부. 운영 조건 분석

아래는 실측이 아니라 이 서비스 상황에 대한 판단이다. 1부의 수치와 구분한다.

## 2-1. 비교표

| 기준 | Local (qwen36) | Cloud (Luna) |
| --- | --- | --- |
| Quality | 유효 정답 70%, 설명 평균 1.30 | 유효 정답 80%, 설명 평균 2.00 |
| Latency | 평균 427.5s. 네트워크 없음 | 평균 254.4s. 네트워크 왕복 포함 |
| Cost | 20회에 추가 과금 없음. 장비·전력·관리 비용은 미측정 | 20회에 $0.5929(추정). 사용량에 비례해 증가 |
| Security | 문제문과 코드가 기기 밖으로 나가지 않음 | 외부 API로 전송됨. 공개·가상 자료만 사용해야 함 |
| Infrastructure | 8 GiB VRAM 노트북에 GGUF·llama.cpp 준비와 서버 상주 필요 | API 키만 있으면 됨 |
| Operations | 서버 기동·설정·VRAM 적합성을 직접 관리. 실패 시 원인 추적도 직접 | 제공자 장애에 종속. 실제로 502·504를 겪음 |
| Customization | 서버 인자·context·reasoning 예산을 직접 조정 가능 | 제공 모델과 API가 노출한 범위 안에서만 |

## 2-2. 이 서비스 상황에서의 권고

용도는 개인 알고리즘 학습이고, 다루는 자료는 공개된 COCI 문제다. 비공개 코드나 개인정보를 넣지 않는다.

**권고는 Cloud 우선, 로컬 병행이다.**

근거는 이렇다. 정답률과 설명 품질에서 Luna가 로컬 최고 후보를 앞서고, 평균 응답 시간도 짧다. 20회에 $0.59이므로 개인 학습 빈도에서 비용 부담이 크지 않다. 자료가 공개 문제라 데이터 통제 요구도 약하다.

그럼에도 로컬을 버리지 않는 이유가 있다. 제공자 5xx로 2회가 실패했는데, 로컬에서는 그 유형의 실패가 없었다. **외부 제공자 장애에 대한 대체 경로로 로컬을 검토할 이유가 있다.** 다만 이번 표본으로 가용성을 정량 입증하지는 않았다. 비공개 코드를 다루는 상황이라면 별도의 데이터 통제 요건에 맞춰 로컬 또는 승인된 외부 처리 방식을 검토해야 한다.

## 2-3. 이번 Cloud 관측과 로컬 선정을 분리한다

발제는 Cloud가 더 높은 품질을 보였더라도 Cloud 결과·로컬 선정 이유·운영 권고를 분리해 설명하라고 한다.

- **Cloud 결과:** Luna는 이번 프로젝트 정답률 80%와 설명 평균 2.00으로 가장 높았다. 성공 응답 평균은 약 254초이며, Motif-3의 약 246초보다 짧지는 않았다. 비용도 모든 모델을 같은 기준으로 비교하지 않았다.
- **로컬 선정:** Cloud를 후보에서 제외하고 로컬 두 후보만 비교해 **qwen36**을 골랐다. 근거는 [최종 선정 보고서](model-selection-report.md)에 있다.
- **운영 권고:** 위 2-2와 같다.

이 셋을 섞지 않는다. Luna가 로컬 통과선을 넘었다고 해서 로컬 후보가 되는 것이 아니고, qwen36이 선정됐다고 해서 실제 운영에서 Cloud보다 낫다는 뜻도 아니다.

## 2-4. 한계

- 공개 문제·풀이의 학습 데이터 포함 여부를 검증하지 않았다. 새로운 문제에 대한 일반화 성능으로 단정하지 않는다.
- 제공자별 생성 설정·토큰 예산이 다르고 일부 평가 정책은 생성 이후 확정했다.

- 평가셋이 10문항이고 한 대의 노트북에서 측정했다. 다른 장비·다른 문제 구성에서 같은 순위가 나온다고 보장하지 않는다.
- Cloud 응답 시간에는 측정 시점의 네트워크와 제공자 부하가 섞여 있다. 시간대별 반복 측정은 하지 않았다.
- Luna 비용은 추정이며 실제 사용 내역과 대조하지 않았다. Motif-3 비용은 산정하지 않았다.
- 로컬 총소유비용을 측정하지 않았다.
- 로컬 두 회차가 상당수 동일해 반복 측정의 의미가 제한된다. 상세는 [생성 기록 진단](../history/generation-diagnostics.md)에 있다.
