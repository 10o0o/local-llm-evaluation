## 3. 선정 근거 상세

### 3-1. qwen36을 선택한 이유

- **유일하게 최소 품질선을 넘었다.** 14/20(70%)으로 12/20 기준을 충족한다. gemma4는 9/20(45%)으로 미달이다.
- **2배 제한 재평가에서 추가로 회복됐다.** `tezina` 두 회차가 공식 1배에서 TLE였으나 4초에서 78/78 AC로 전환됐다(최대 케이스 2.59초, 2.61초). 해당 테스트 집합에서 시간 제한 완화 후 통과한 관측이다. Python 상수 비용만이 원인이라고 분리 검증한 것은 아니다.
- **응답 시간이 gemma4의 1/3.8이다.** 평균 427.5초 대 1,606.3초다.
- **호출 실패가 없었다.** 20/20 전부 성공했다.

### 3-2. gemma4를 탈락시킨 이유

- **원본 정답률 45%로 통과선 미달이다.**
- **2배 제한으로 회복된 항목이 하나도 없다.** TLE가 0건이고, `pet`의 시간 초과 테스트는 원본이 이미 WA라 시간을 늘려도 정답이 되지 않았다.
- **응답 시간이 문항당 평균 26분이다.** 개인 학습용으로 쓰기 어려운 수준이다.
- **긴 응답에서 reasoning 반복이 관측됐다.** 10문항 중 8문항에서 12-gram 반복률이 50~92%이고, 같은 구절이 최대 1,085회 반복됐다. 대조군인 qwen36은 대부분 12% 미만이다. 상세는 [생성 기록 진단](../history/generation-diagnostics.md)에 있다.

### 3-3. 대표 성공·실패 사례

**성공.** qwen36 `tomahawk`는 온도를 T(r,c)=A(r)+B(c)로 분리해 최대·최소 차가 각 성분 차의 합이 됨을 보이고, B의 볼록성에서 삼분 탐색을 정당화한 뒤 130/130을 통과했다. 설명과 결과가 일치한 사례다.

**실패 1 — 설명 없이 코드만.** qwen36 `pet`·`ucionica`는 최종 답변이 코드 블록 하나뿐이고 산문이 0자다. 지시한 접근법·복잡도 설명이 아예 없어 설명 점수 0점이다. 두 문항 모두 reasoning 사용량이 qwen36 평균보다 높았다.

**실패 2 — 코드가 실행조차 안 됨.** gemma4 `struktura` round_1과 `tomahawk` round_1은 마지막 줄이 `solve()`가 아니라 **`solve`** 였다. 함수가 호출되지 않아 출력이 없었고 각각 0/130이었다. 괄호를 붙이자 둘 다 130/130 AC가 됐다.

**실패 3 — 설명한 알고리즘을 구현하지 않음.** gemma4 `ucionica` 두 회차는 세그먼트 트리 풀이를 본문에 설명해 놓고 코드는 `pass`로 끝나며 "완전한 구현을 제공하겠다"는 주석만 남겼다. 0/91이다.

**실패 4 — 출력 한도 소진.** `skijanje`(난이도 9)는 로컬 두 모델 모두 `finish_reason=length`로 코드 블록을 닫지 못했다.

실패 원인을 모델·프롬프트·환경·측정으로 나누어 살폈다.

## 5. 한계

### 5-1. 반복 측정이 실제로는 절반이다

`temperature=0`으로 수행한 **qwen36의 10문항은 전부 두 회차 응답이 바이트 단위로 같다.** gemma4는 5/10이 같다. 즉 qwen36의 20회에는 10개 고유 응답의 반복 기록이 포함된다.

회차 중복을 보정해 고유 응답만으로 다시 계산하면 이렇다.

| 모델 | 규정 분모(20) | 고유 응답 기준 |
| --- | ---: | ---: |
| qwen36 | 14/20 (70%) | 7/10 (70%) |
| gemma4 | 9/20 (45%) | 8/15 (53%) |
| luna | 16/20 (80%) | 16/20 (80%) |
| motif3 | 13/20 (65%) | 13/20 (65%) |

luna·motif3는 회차 중복이 없어 보정값이 규정 분모와 같다. motif3의 호출 실패 2건은 서로 다른 시도이므로 하나의 고유 응답으로 묶지 않고, [요구사항](requirements.md)의 분모 규칙대로 20에 남긴다.

**보정 후에도 qwen36(70%)이 gemma4(53%)보다 앞서므로 선정 결론은 바뀌지 않는다.** 다만 Qwen에서는 두 회차 간 응답 변동을 관측하지 못했다. 주 지표는 요구사항이 정한 20회 분모를 유지한다.

### 5-2. 그 밖의 한계

- **공개 문제의 학습 데이터 오염 가능성을 검증하지 않았다.** 문제나 풀이가 모델의 학습 자료에 포함됐는지 확인하지 못했다. 따라서 새로운 문제에 대한 일반화 성능으로 단정하지 않는다.

- **평가셋이 10문항이다.** 난이도 1~9로 분포시켰지만 작은 표본이며, 모델 간 차이의 통계적 유의성을 검증하지 않았다.
- **장비가 한 대다.** 8 GiB VRAM 노트북 한 대의 결과이며 다른 장비의 절대 속도와 합치지 않는다.
- **메모리 제한을 강제하지 않았다.** Judge는 시간 제한과 출력 제한만 적용하고 RSS 측정·MLE 판정을 구현하지 않았다. **따라서 AC는 보유한 테스트를 통과했다는 뜻이지 메모리 제한 준수를 증명하지 않는다.**
- **평가 기준이 사전등록되지 않았다.** 생성이 시작된 뒤 확정했다(`preregistered=false`). 2배 제한을 적용할 네 문항도 생성 이후에 정했다.
- **설명 점수는 채점자가 한 명이고 교차 검토가 없다.** 78건 각각에 최종 답변에서 인용한 근거를 달았지만, 같은 응답을 다른 사람이 채점했을 때 같은 점수가 나오는지는 확인하지 않았다.
- **재생성으로 원인을 확인할 수 없었다.** GGUF와 llama.cpp 런타임이 이 기기에 없다.

### 5-3. 조건을 하나로 고정할 수밖에 없었던 이유

최종 benchmark는 **temperature 0, context 65,536, 출력 61,440, reasoning 53,248을 기준으로 한 비교**다. 이 비교 전후로 GPU 레이어·CPU MoE·스레드 등 추론·서빙 옵션은 직접 바꿔 보았지만, 모든 조합을 동일 평가셋으로 대조한 기록은 아니다. 최종 비교 조건을 추가하지 못한 데는 실행 시간 제약이 있었다. 현재 셸 값과 과거 실행 조건의 차이는 [환경 기록](../operations/environment.md)을 따른다.

로컬 생성에 실제로 쓴 벽시계 시간은 다음과 같다.

| 모델 | 문항당 평균 | 20회 합계 | 출력 토큰 합 |
| --- | ---: | ---: | ---: |
| qwen36 | 6.9분 | 2.4시간 | 331,402 |
| gemma4 | **26.6분** | **8.9시간** | 1,089,071 |
| 로컬 합계 | — | **11.3시간** | 1,420,473 |

문항당 시간은 대부분 생성 속도가 아니라 **출력량**이 정한다. 두 모델의 생성 속도는 34~40 tok/s로 비슷한데, Gemma는 reasoning 예산 53,248을 거의 매번 소진해 문항당 약 5만 토큰을 뱉는다. 60k에 가까운 출력을 30 tok/s대로 채우면 산술적으로 문항당 30분 안팎이고, 실측 26.6분이 정확히 그 값이다.

같은 출력량과 실행 속도가 유지된다면 **조건 한 세트를 추가하는 데 로컬에서 약 11시간이 더 필요하다는 추정**이다. 새 설정에서는 출력량과 실행 시간이 달라질 수 있다. 실험 일정과 설정을 네 번 동결·재시작한 이력이 겹쳐, 아래 조건들은 검토만 하고 실행하지 못했다.

- **temperature > 0의 반복 측정.** 5-1의 응답 중복과 설정 변화의 관계를 확인할 후속 비교다. temperature 변경만으로 표본의 독립성이나 성능 향상을 보장하지 않으며, 같은 평가셋의 재실행이 필요하다.
- **reasoning 예산을 줄인 Gemma 재실행.** 반복과 예산 설정의 관계를 확인할 대조 조건 중 하나다.
- **문항 수 확대.** 10문항에서는 정답률 5%p가 한두 문항으로 움직인다.
- **동일 모델 양자화 비교.** 양자화 버전 간 성능 차이는 별도로 측정하지 않았다.

**따라서 이 결과는 "이 설정 조합에서의 비교"로 읽어야 한다.** 다른 temperature나 다른 예산에서 두 모델의 순위가 같다는 근거는 이 실험에 없다.

## 6. 실제 도입 가능 여부

선정된 qwen36은 최소 품질선을 넘었지만 **70%는 개인 학습 보조로 쓸 수 있는 수준이지 제출 코드를 신뢰할 수 있는 수준이 아니다.** 10문항 중 3문항에서 원본이 틀렸고, 난이도 7 이상에서는 `prepisivanje` 한 문항만 통과했다.

실제 사용 시에는 생성 코드를 그대로 제출하지 말고 로컬 채점을 거치는 것을 전제로 한다. 이번 문제 집합에서는 난이도가 높은 문항에 Cloud를 함께 검토하는 쪽을 택했다. 다른 문제·장비·생성 설정에서도 같은 선택이 최선이라는 뜻은 아니다.
